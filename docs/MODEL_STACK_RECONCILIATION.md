# Micromix model-stack reconciliation

Audit and first four implementation slices: 2026-11-13. Active backlog: [`../PLAN.md`](../PLAN.md), task 23. This is **not completion of the full modernization**. No weights were installed, changed or downloaded; no real-model inference, quality assessment, performance benchmark or desktop automation was performed. Existing manual acceptance gates remain open.

## Decision

Retain the current proven integration surfaces. Make routing and backend evidence consistent before introducing a new engine. Keep the native product local/private; no web UI, public server, deployment infrastructure or heavyweight orchestrator. Add conventional MLX separation and structured covers only after checkpoint-specific licensing and user-led audio evaluation. Preserve existing project/assets/preset identifiers.

Implemented so far:

- A lightweight generation capability registry drives API catalog/limits, operation validation, worker-environment selection, ACE model/step selection and worker pre-load rejection. Existing preset IDs remain unchanged, including the legacy `minimax-cover` ID; it still means **text generation only**. Native Generate/Reimagine now consume the catalog: operation-specific engine choices, explicit loading/failure/empty states, and per-engine limits/settings validation. The catalog also names the health marker to use via `health_model`.
- Per-variation ACE provenance separates configuration (`backend_states`) from observed component calls (`execution_traces`). The latter counts diffusion, VAE-decode and PT-planner attempts/successes/failures, including MLX failure followed by PyTorch/CPU fallback. Successful and failed input devices are kept separately; unobserved components remain unknown. These are call boundaries, not kernel traces or whole-pipeline backend guarantees.
- A shared native content-addressed analysis cache reuses summaries across existing Analyze, guided remix and transcription callers. Source SHA-256, analyzer schema and OS build/native-API availability identify entries; corrupted records recompute, changed sources invalidate, concurrent identical requests coalesce. No Library database migration. This cache is recomputable metadata, **not** a new project store or portable project bundle.

## Target workflows and shared data flow

Use existing Library files/SwiftData and durable sidecar assets/jobs as authorities. A future Song/project record should reference those IDs, source content hashes and optional typed relations; it should not copy every asset into a second independent database.

1. **Faithful vocal cover:** source → one selected music separator → original-timebase vocal → trained RVC → instrumental + converted vocal in Timeline → render. No ACE, YuE2 or MIDI prerequisite. Preserve source length/sample alignment; handle lead/backing separately only if the selected separator actually supports it. Current guided flows/stem outputs can be reused, but one-click faithful recombination and alignment quality are not complete.
2. **Audio-driven reimagining:** source → optional cached native analysis → ACE cover conditioning → alternative assets with lineage → Timeline. Genre/production belongs in caption; source strength/metadata/lyrics are separate constraints. It is not a guarantee of note-for-note identity.
3. **Structured reimagining:** source → selective SheetSage2/MERT2 melody/harmony/ABC → reviewed score/lyrics section proposal → YuE2 acoustic synthesis. Composition, transcription and acoustic rendering have distinct requests/seeds/artifacts. Do not recompute composition when only production/synthesis changes. This is a gated future slice, not implemented or advertised today.
4. **Arrangement reconstruction:** optional stems → MuScriptor multitrack MIDI → correction/instrument assignment → actual instrument rendering → optional audio refinement/voice conversion → Timeline. No automatic MIDI-to-generative-audio assumption. Native MIDI editor/renderer is not yet implemented.

New cache data lives under the user's `Caches/Micromix/MusicAnalysis`; it can be deleted without losing source media. Hashing reads 1 MiB chunks off the main actor. Failed computations and changed-during-analysis sources are not published; atomic JSON writes are best effort. In-flight native analysis is shared; a cancelled waiter returns without cancelling other callers. The last departing waiter cancels the computation and prevents stale cache publication. Native APIs may still ignore cooperative cancellation internally; prompt model-resource release is not guaranteed. Hashing runs outside the cache actor, and each caller's source is revalidated before return. Cache records are intentionally not portable project metadata, and disk eviction is left to the user/OS for this small derived cache. Full structured analysis should later become a versioned portable Library artifact with beat/bar/range units and analyzer provenance.

## Local derivation compatibility and portability

`LibraryItem.derivation` records a local operation and parent Library UUIDs without fabricating a sidecar job or remote output. New corrected lyrics use it; their display text no longer embeds an ID. Related-assets lookup treats explicit IDs as authoritative, deduplicates matches and retains exact-format text parsing only for legacy corrections.

The existing nullable `LibraryRecord.provenanceData` blob stores a version-1 envelope only for items with local derivations. Remote-only items keep their previous raw `LibraryProvenance` JSON. Reads support both forms, so no SwiftData schema or store migration is needed. Unsupported envelope versions are ignored for relationship resolution and their raw stored bytes are not rewritten by a read. This is not a complete future-format import/export guarantee.

Bundle JSON includes the typed derivation through the existing item manifest; available direct parents are collected using existing lineage grouping. Text notes distinguish `LIBRARY ITEM` from a real remote `JOB` and report unavailable local parent IDs. Parent removal does not cascade-delete corrections or discard their parent references. UUID relations establish local lineage, not cryptographic content identity or exact reproduction; portable analysis still needs source/analyzer hashes and an explicit artifact contract. No shared Song aggregate, MIDI editor or score store was added.

## Apple audio/platform boundary

Continue public AVFoundation/AVAudioEngine for decode, playback and audio rendering. Keep Accelerate/Core ML as implementation options only where a measured preprocessing/inference bottleneck or a maintained model conversion warrants them. No conversion just to satisfy an MLX preference. Audio Unit hosting is not required for the bounded audio-first editor. Logic Pro remains an optional manual handoff; its application features do not establish public reusable stem-separation/model APIs. Do not extract Logic models or use private frameworks. Beat snapping needs stored timestamped beats; BPM alone is not a valid nonsteady beat grid.
