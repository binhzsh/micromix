**Source inspection, not a runtime evaluation.** No Studio dependencies, models, desktop app, server or benchmarks were run. No Studio code was copied. Treat it as a reference, not a new Micromix dependency.

## Patterns and actual implementation

All paths below are relative to the pinned [Studio tree](https://github.com/timoncool/YuE2-Studio/tree/79cf4facf2f4c8764a076baf73a51bfc7f428b1f).

| Area | Source evidence | Micromix decision |
| --- | --- | --- |
| Score first | `crates/music-server/src/lib.rs`, `compose_score` (~11348); `src/mcp.rs` (~1539). Composition submits a separate job; parser extracts ABC and LM seed from replay request. User selects a plan before acoustic synthesis. | Preserve this separation if structured covers pass evaluation. An ABC score is an editable intermediate artifact, not generated audio and not automatically full multitrack MIDI. Do not add an unused score engine now. |
| Source cover | `lib.rs`, `create_transcription` (~11365): source library/upload, decode unsupported containers to WAV, call configured engine `/transcribe`; SheetSage2 output ABC becomes cover conditioning. `melody_only` removes chord symbols. | Reuse current asset upload/job/lineage seams; only transcribe when a structured-cover request needs it. SheetSage2/MERT2 must remain distinct from MuScriptor full MIDI reconstruction. No quality inference from this orchestration code. |
| Section alignment | `src/score/section_match.rs`: first recognized lyric-line time maps a block to score sections; one-bar pickup allowance; late/non-monotonic placements become unsure; empty sung sections may propose a repeated same-kind block. | Useful algorithmic reference, but a reviewable proposal only. Do not silently duplicate lyrics or assert semantic verse/chorus identity from acoustic segments. Require timestamps, meter and explicit uncertainty. Current Whisper adapter emits plain text, so automatic integration would fabricate missing timing evidence. |
| Score edit validity | `src/score/edits.rs`: truncated SHA-256 fingerprint over style, lyrics and mode; explicit keep override for stale edits. | Future edited-score identity should include score/transcriber revision and source hash as well. Current analysis cache adopts only the general content/config identity principle, independently implemented. |
| Replay | `src/library.rs` (~10), `src/mcp.rs` (~1527): stores settings, engine/profile, replay request, optional audio codes, and derived source/tool metadata. | Reuse existing `LibraryProvenance`/`runtime_provenance`, not another database. Preserve codes only when actually returned, version their format and store as an artifact, not huge inline UI data. Seeds alone do not reproduce a score or waveform. No current Micromix audio-code replay claim. |
| MIDI edits | `app/components/midi/MidiEditor.tsx` (~30); `src/score/api.rs` (~115, ~151): embedded signal fork, ABC→MIDI editing→ABC, separate voice/instrument/chord tracks; seeded deterministic chord-bed endpoint. | Do not embed the web editor. Native editable score/MIDI requires its own approved scope, round-trip loss tests and renderer; current Timeline is audio-first. A chord progression is not a stem or accompaniment waveform. |
| Recovery | `src/library.rs` (~119), `lib.rs` (~559): full requests/status/attempt/resumed_as; wait for readiness, resubmit interrupted jobs up to a limit and link cancelled original to retry. | This is resubmission, not checkpoint continuation. Micromix already has supervised disposable workers, SQLite recovery and group cancellation. Do not replace them with the Studio server. Consider bounded retry lineage separately; never silently loop expensive failed jobs. |
| MCP | `src/mcp.rs` (~144): tools wrap existing composition/transcription/song/job/replay actions; compact results omit large codes unless requested. | Keep one authoritative capability/job API; observable actions and bounded response sizes are useful. ## What can be adopted under its license?

The top-level [Studio license](https://github.com/timoncool/YuE2-Studio/blob/79cf4facf2f4c8764a076baf73a51bfc7f428b1f/LICENSE) and pinned [yue2.cpp license](https://github.com/timoncool/yue2.cpp/blob/46a0c9109107bf5ad55675b388a58deff3c3b848/LICENSE) are MIT: original code may be adapted with copyright and permission notices retained. This does **not** blanket-license every bundled component.

Studio's README license inventory identifies Apache-2.0 score/MIDI code originating in YuE2-ComfyUI, an AGPL-3.0 visualizer, and GPL-2.0 A320U SoundFonts. The embedded editor has its own notices. Before copying any particular function, inspect its file headers, origin and dependency notices; retain Apache NOTICE/attribution where required. The most relevant adaptation candidates are the section-matching heuristics and score-edit fingerprint, but they should be independently implemented against typed Micromix artifacts after the required inputs exist. No code adoption is needed for the current cache/routing slice.

Software licensing is separate from YuE2, SheetSage2, MERT2 and auxiliary checkpoint rights. The original [YuE2-3B card](https://huggingface.co/m-a-p/YuE2-3B) identifies CC BY-NC 4.0. A broader [YuE model-license document](https://github.com/multimodal-art-projection/YuE/blob/main/MODEL_LICENSE) describes individual-creator permissions with conditions; that mutable family-level document is not proof those exceptions apply to every YuE2 checkpoint. Studio says SheetSage2 and Mothersuperior lack that permission. Resolve rights at exact checkpoint revisions; a conversion's Apache/MIT badge cannot override upstream weight terms. Source-song, lyric and voice authorization remain separate.

## M2 Max comparison protocol — user-led, not executed

1. Confirm the same upstream YuE2 checkpoint and licensed auxiliary components can be represented in both backends. Record commits, weight hashes, AR precision, KV-cache type, VAE, acoustic steps and duration limits. If not equivalent, label it a configuration comparison, not backend parity.
2. Fix source audio, supplied ABC and lyrics. Compare acoustic-only synthesis separately from score composition and transcription. Test 32-step and fast synthesis as separate quality/speed tradeoffs; do not equate their outputs.
3. Measure cold initialization, warm composition, transcription, synthesis and decode separately, wall time, real-time factor and process-tree peak/unified memory pressure. Do not compare an M3/M5 published number to M2 Max.
4. For covers, manually check melody contour, chord identity, pickups, lyric syllable/section placement, duration, intelligibility and artifacts. Same seed across frameworks is not proof of equivalent randomness. Keep outputs and settings for blinded listening.
5. Check cancellation, missing models, process exit/recovery, and exact saved-code re-synthesis within one backend/version. Distinguish replaying acoustic codes from rerunning composition. Do not promise bit-identical audio without a measured repeatability test.

No implementation/backend selection is contingent on winning a published aggregate benchmark. A structured-cover engine is justified only if it preserves identity meaningfully better on the user's material at acceptable runtime and licensing cost.
